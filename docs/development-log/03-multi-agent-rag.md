# 阶段03：多智能体RAG问答

## 阶段目标

把原有“检索后直接生成”的单链路问答升级为“检索—校验—生成—审查”的多角色协作流水线，提高专业问答的可追溯性和稳定性。

## 主要成果

- 检索智能体：识别任务类型并宽召回候选资料；
- 校验智能体：按相关性和来源权威度重排，去重并过滤低相关内容；
- 生成智能体：根据任务类型生成带编号引用的答案；
- 审查智能体：检查答案完整性、引用缺失和引用编号越界；
- 审查未通过时最多触发一次修正并再次审查；
- 支持概念、推导、代码、论文、比较、故障排查、游戏攻略和学习路径路由；
- 返回校验报告、审查结果、置信度和智能体执行追踪；
- 建立问答会话历史的保存、查询和删除接口；
- 加入不执行用户代码的Qiskit AST静态诊断。

## 架构说明

“多智能体”在当前版本中表示多个职责明确、可独立测试的角色模块，并不意味着必须部署四套不同的大模型。检索、校验和审查中的部分能力采用确定性规则，生成和修正使用配置的大模型。

这种实现更适合作为MVP：成本可控、行为可测试，也便于后续把某个节点升级为专用模型或独立服务。

## 已知限制

- 当前审查主要验证引用和回答结构，不能形式化证明量子结论正确；

- 真实效果仍依赖知识库资料质量。
