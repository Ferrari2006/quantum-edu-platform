# 阶段09：引导式线路实验与自动验收

## 阶段目标

解决“推荐进入线路实验室后仍面对空白画布”的问题。把线路类学习建议转换成有目标、有步骤、有反馈的教学任务，让学习者能够完成一次可验收的动手练习，而不只是自由试验。

## 输入与上下文

- 相关反馈：开发重心应逐步转向用户资料库和教学问题；
- 前置能力：图形化线路实验室、目标态保真度、概念掌握度和行动推荐；
- 本阶段范围：受限状态矢量模拟下的基础线路任务；
- 不在范围：测量与经典寄存器、噪声模型、正式考试和教师自定义题库。

## 主要成果

### 五个引导式任务

1. 用H门制备叠加态；
2. 用X门完成量子比特翻转；
3. 通过H—Z—H把相位差转换为可见结果；
4. 从叠加制备Bell纠缠；
5. 把两比特关联扩展为三比特GHZ态。

每项任务均包含：中英文标题、教学目标、预计时间、三步操作、可按需显示的提示、完成后反思问题、线路脚手架和关联概念。

### 自动验收

- 验证量子比特数量；
- 验证是否使用任务要求的关键量子门；
- 验证线路步骤数量；
- 使用后端返回的目标态保真度检查是否达到98%；
- 在页面显示逐项通过状态、失败反馈和完成后的反思问题；
- 自动验收逻辑为独立纯函数，可直接进行前端单元测试。

### 教学证据与推荐联动

- 未通过的任务记录为`lab_attempt`，权重低于正式完成；
- 通过任务记录为`lab_completed`；
- 事件元数据保存任务ID、是否通过、验收项、门序列和保真度；
- 每次任务运行生成幂等键，避免一次网络请求重复计入；
- 叠加、相位、单比特门、CNOT、Bell态等推荐会携带`task`参数；
- 实验室从`/#/lab?task=...`读取参数并自动加载对应脚手架；
- “让AI解释线路”会同时携带当前任务目标和反思问题。

## 重要决策

- 以保真度而非门序列完全相等作为核心验收标准，允许学习者探索等价线路；
- 同时要求关键门和最少步骤，避免仅靠偶然或无关线路通过；
- 失败尝试仍作为低权重诊断证据，而不等同于任务完成；
- 任务定义放在前端静态目录，适合当前MVP；未来教师端上线后再迁移到后端课程服务。

## 验证

- 前端7项自动化测试全部通过，其中2项覆盖实验任务目录和Bell任务验收；
- 学习服务8项核心测试通过，2项因精简运行环境没有FastAPI而跳过；
- 多智能体RAG 13项回归测试通过；
- 前端生产构建通过，共转换120个模块；
- 使用无界面浏览器检查`/#/lab?task=bell-pair`，确认任务脚手架、教学说明、画布和结果区布局正常。
- 全目录自动发现会尝试加载旧的pytest/Qiskit测试；当前精简运行环境缺少`pytest`和`qiskit`，因此本阶段采用上述相关模块回归，未把依赖缺失误记为代码失败。

## 已知限制

- 当前任务目录为前端静态数据，教师尚不能在页面上新增或修改任务；
- 自动验收基于理想状态矢量模拟，尚未模拟真实设备噪声；
- 任务失败会影响掌握度估计，权重仍是MVP启发式参数；
- 当前任务不包含测量门、经典条件和多轮采样；
- 页面自动化测试覆盖规则逻辑，尚未加入浏览器端点击流程测试。

## 下一阶段建议

- 增加任务完成历史、最佳成绩和连续学习目标；
- 让薄弱点推荐自动选择任务难度；
- 建立教师端任务和小测题库管理；
- 加入噪声模型，比较理想保真度和带噪保真度；
- 增加测量、经典寄存器和基于采样次数的统计实验。
