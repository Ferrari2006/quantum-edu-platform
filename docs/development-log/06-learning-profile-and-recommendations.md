# 阶段06：学习画像与教学推荐闭环

## 阶段目标

按照团队“把重点转向面向用户资料库和教学”的反馈，把知识库、量子线路实验室与账号体系连接起来。系统不只展示资料，还要能够记录学习行为、估算概念掌握度，并给出下一步学习建议。

## 主要成果

- 新增统一学习事件模型，支持资料完成、实验完成、小测、游戏结果和提问等证据类型；
- 新增概念掌握度表，按证据权重汇总同一概念在不同教学场景中的表现；
- 文章完成事件支持幂等键，避免重复点击导致掌握度虚高；
- 建立与知识库21个主题一致的第一版概念目录；
- 新增学习事件、概念掌握度、学习时间线和推荐接口；
- 知识库首页新增个人学习画像卡片，显示平均掌握度、概念覆盖数和推荐主题；
- 登录用户标记文章完成后，会在保留本地进度的同时同步学习证据；
- 量子线路运行成功后，系统根据门类型、目标态和保真度，将证据归入叠加、Bloch球、CNOT或Bell态等概念；
- 后端同步失败不会阻断文章阅读或线路实验，保障基础功能可离线退化。

## 教学模型说明

当前掌握度是MVP阶段的“学习证据汇总”，不是严格的能力测验分数：

- 阅读完成的证据权重为0.8；
- 量子实验完成的证据权重为1.0；
- 小测结果权重为1.2；
- 游戏结果权重为0.7；
- 提问行为权重为0.25；
- 同一概念的掌握度采用加权平均，保留证据数量和最近更新时间。

因此，阅读和实验可以更新学习画像，但后续仍需用概念小测、实验任务完成度和游戏关卡表现进行校准。不能把“点过完成”直接等同于“已经掌握”。

## API

以下接口均要求Bearer登录令牌：

- `POST /api/learning/events`：提交一条学习证据；
- `GET /api/learning/events`：读取用户学习时间线；
- `GET /api/learning/mastery`：读取概念掌握度与汇总；
- `GET /api/learning/recommendations`：读取按薄弱概念和课程顺序生成的学习建议。

事件主体示例：

```json
{
  "concept_id": "bell-state",
  "event_type": "lab_completed",
  "source": "quantum_lab",
  "score": 0.96,
  "metadata": {
    "num_qubits": 2,
    "gates": ["H", "CX"],
    "target": "bell",
    "fidelity": 0.96
  }
}
```

## 已知限制

- 推荐算法当前基于固定课程顺序与掌握度阈值，尚未加入前置知识图谱；
- 文章本地完成状态与服务端事件还不是双向同步；
- 小测和游戏已预留事件类型，但界面尚未提交这两类事件；
- 概念掌握度是启发式估计，尚未经过真实学习数据校准；
- 教师端查看班级画像、手动修正和导出功能尚未实现。

## 下一阶段建议

- 为重点文章增加3–5道概念小测，让掌握度主要由可验证结果驱动；
- 将两个独立游戏的结算结果通过统一事件接口回传；
- 建立概念前置关系和知识图谱，改进推荐顺序；
- 增加用户学习历史页和教师端学习分析页；
- 把更多知识库“框架文章”补充为经过专业审校的正式内容。
