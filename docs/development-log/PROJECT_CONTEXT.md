# 项目上下文与开发约束

本文为团队成员和后续Codex任务提供稳定上下文。具体需求以当次用户请求和仓库当前状态为准。

## 产品定位

量智启学不是单纯的游戏集合，而是“学习者知识库 + AI伴学 + 量子实验 + 游戏化学习”的统一量子启蒙平台。游戏用于降低理解门槛，知识库和教学闭环是长期核心。

## 当前架构边界

- 前端：Vite + React；
- 后端：FastAPI；
- 本地数据：SQLite；
- RAG语料：`docs/quantum/`；
- 学习者内容：前端知识内容模型及后续内容服务；
- 游戏核心：`games/game1`和`games/game2`；
- 游戏Web适配：`backend/api/game_routes.py`；
- 多智能体RAG：`backend/rag/agents.py`。

## 开发约束

1. 保持现有API兼容，修改接口时优先采用可选字段和渐进迁移；
2. 两套游戏的核心规则保持模块独立，通过统一API接入平台；
3. AI攻略通过结构化状态输入和建议结果输出，不直接替用户操作游戏；
4. 不执行未经隔离的用户代码；
5. 不把API Key、Token、密码和个人隐私数据提交到仓库；
6. 知识回答必须保留来源和版本信息，不把模型输出描述为绝对正确；
7. 学习路径使用“推荐”表述，不宣称客观最优；
8. 编辑时保留用户已有修改，避免无关的大范围重写；
9. 功能改动必须提供与风险相称的测试或构建验证；
10. 每个阶段完成后更新本目录中的开发记录、限制和版本信息。

## Git协作约定

- `main`保持可运行；
- 较大功能在独立分支开发；
- 提交信息简短说明结果；
- 通过Pull Request审阅后再进入`main`；
- 不把本地数据库、模型密钥、构建缓存和依赖目录提交到仓库。

## 当前优先级

1. 完成多智能体RAG MVP的审阅与合并；
2. 扩充面向用户的知识内容和权威检索语料；
3. 建立学习目标、概念掌握度和推荐闭环；
4. 建立教学与检索评测集；
5. 再推进图形化量子线路实验室和隔离执行能力。
