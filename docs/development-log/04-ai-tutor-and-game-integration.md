# 阶段04：AI伴学入口与游戏联动

## 阶段目标

把多智能体后端能力开放给普通学习者，并通过标准接口把游戏实时状态作为攻略生成的输入。

## 主要成果

- AI伴学页面增加自动识别、概念解释、算法推导、Qiskit纠错、游戏攻略和学习路径模式；
- 代码模式提供专用输入区，并明确代码不会被直接执行；
- 游戏攻略模式在提问时自动读取`GET /api/quantum-game/state`；
- 前端从完整游戏状态中筛选必要字段，作为`game_state`提交给`POST /api/rag/ask`；
- 问答结果展示置信度、审查状态、引用来源、检索片段和各智能体耗时；
- 未开始游戏时给出明确提示；
- 完成中英文文案和移动端布局。

## 游戏输入输出模式

```text
游戏引擎/状态
    ↓ GET /api/quantum-game/state
AI伴学页面压缩必要字段
    ↓ POST /api/rag/ask（mode=game_strategy）
多智能体RAG生成策略
    ↓
返回建议、理由、风险、量子知识和引用
```

当前策略结果只作为学习和通关建议展示，不会自动替玩家操作游戏，也不会直接修改游戏状态。

## 两个游戏的关系

两套游戏源码和核心规则保持模块独立，便于分别维护和测试；但在产品层面不是两个与平台无关的孤立产品。它们共用平台入口、统一后端前缀`/api/quantum-game`和AI伴学联动方式。

原有桌面原型可以继续单独运行，Web平台则通过后端适配层复用核心状态和计算逻辑。
