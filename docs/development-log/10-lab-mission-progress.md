# 阶段10：实验任务进度与最佳成绩

## 阶段目标

让引导式实验不再是一次性页面操作。学习者重新进入线路实验室时，应知道完成了哪些任务、尝试了多少次、历史最好结果如何，从而形成可持续的练习反馈。

## 主要成果

### 后端任务进度聚合

- 新增`GET /api/learning/lab-progress`登录接口；
- 从最近500条学习证据中识别5个正式引导任务；
- 按任务汇总尝试次数、是否完成、最佳证据分数、最佳保真度、最近尝试时间和完成时间；
- 返回总任务数、已完成数和总尝试数；
- 没有记录的任务也会返回零值，前端无需自行补齐目录。

### 学习者界面

- 实验任务区显示“已完成/总任务数”；
- 已完成任务显示绿色完成状态；
- 未完成但尝试过的任务显示尝试次数；
- 当前任务显示历史尝试次数和最佳保真度；
- 未登录用户看到保存成绩的登录入口；
- 每次任务证据同步成功后自动刷新任务进度。

## 重要决策

- 直接聚合已有不可变学习事件，不新增一张容易与事件记录失去一致性的任务状态表；
- 任务完成以通过验收的`lab_completed`事件为准，失败的`lab_attempt`只增加尝试数；
- MVP最多读取最近500条证据，避免无限扫描；任务量和使用量扩大后应改为数据库聚合查询或专用统计表；
- 接口只返回学习数据，不把前端教学文案复制到后端，双语标题继续由任务目录维护。

## 验证

- 学习服务9项核心测试通过，2项因精简运行环境缺少FastAPI而跳过；
- 新增测试覆盖失败尝试、成功完成、最佳分数、最佳保真度和汇总数量；
- 前端7项测试全部通过；

- 相关Python文件语法检查通过。

## 已知限制

- 进度统计目前最多读取最近500条学习事件；
- 尚未展示单项任务的完整尝试时间线；
- 没有周目标、连续学习天数和提醒；
- 最佳结果适用于理想状态矢量模拟，尚未区分带噪设备成绩。

## 下一阶段建议

- 在学习档案中加入实验任务筛选和成绩趋势；
- 增加每周任务目标和连续学习天数；
- 支持教师发布任务集合与截止时间；
- 引入噪声模型后分别记录理想与带噪最佳成绩。
